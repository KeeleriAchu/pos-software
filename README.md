# POS Application – Documentation

## 📖 Overview
A full‑stack Point‑of‑Sale (POS) system built with **Node.js/Express** on the backend, **Supabase (PostgreSQL)** as the database, and a **Vite‑React** frontend.  The code is organized into separate **frontend** and **backend** folders.

---

## 🏗 Architecture
```mermaid
flowchart TD
    UI[Front‑end (React/Vite)] -->|HTTP API| API[Backend (Express)] -->|Supabase SDK| DB[(Supabase PostgreSQL)]
    API -->|File system| Backup[./backups folder]
    UI -->|Bearer JWT| Auth[requireAuth middleware]
```
- **Frontend** – React components, pages, and services under `frontend/`.
- **Backend** – Express router files under `backend/routes/`, utilities under `backend/utils/`, and services like `backup.js`.
- **Auth** – JWT based, using `backend/middleware/auth.js`.
- **Backup** – JSON dumps stored in `./backups` and CSV export endpoint.

---

## 🔐 Authentication
- **Register** – `POST /api/auth/register` – bcrypt‑hashes password, stores user, returns JWT.
- **Login** – `POST /api/auth/login` – validates credentials, returns JWT.
- **Middleware** – `requireAuth` verifies token, attaches `req.userId` / `req.user`.  All protected routes use `router.use(requireAuth)`.

## ⚙️ How to Run Locally
1. **Clone / open the repository**
2. **Backend**
   ```bash
   cd backend
   npm install
   cp .env.example .env   # set JWT_SECRET, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, etc.
   npm run dev   # starts Express (default PORT 5000)
   ```
3. **Frontend**
   ```bash
   cd frontend
   npm install
   npm run dev   # Vite dev server, usually http://localhost:5173
   ```
4. **Database** – The project uses Supabase.  Create a Supabase project, run the SQL files in `NEW_DATABASE_SETUP.sql` / `NEW_TABLES.sql` to create tables (`users`, `products`, `customers`, `bills`, …).
5. **Backup** – Backups are stored under `./backups`.  Ensure the folder exists and the process has write permission.

## 📈 Typical User Flow
1. **Sign‑up / Login** – obtain JWT.
2. **Navigate to Products page** – UI fetches `/api/products`.
3. **Create / Edit / Restock** – UI sends POST/PUT/PATCH requests; backend validates, updates Supabase, logs audit.
4. **Low‑stock alerts** – `is_low_stock` flag shown on UI.
5. **Admin Backup** – Admin clicks “Run Backup”; frontend calls `/api/backup/run`, then `/api/backup/list` or `/api/backup/download/:name` to retrieve files.
6. **Export CSV** – Admin clicks “Export CSV”, receives a JSON payload with CSV strings for each table.
